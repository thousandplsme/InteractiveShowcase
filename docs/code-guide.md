# Prototype 0の技術・コード解説

## 全体の流れ

```text
カメラ → Pythonで顔の位置を計算 → UDPで数値だけ送る → Unityが円を移動
```

Pythonは「目」、Unityは「表示係」です。両者を分けることで、後でUnityの表示を変えても顔検出の仕組みを作り直さずに済みます。

## Pythonの役割

- `vision/main.py` は司令役です。カメラ画像を1枚読み、検出を頼み、その結果を送る処理を繰り返します。終了やカメラの失敗時には、カメラ・検出器・通信口を閉じます。
- `vision/face_detector.py` はMediaPipe Face Meshの顔landmark（顔の目印）を受け取ります。点の左右上下の範囲から四角形を求め、その中心を顔位置とします。鼻先だけを追う処理ではありません。
- `vision/udp_sender.py` は結果をJSON文字列にして送ります。画像自体は送りません。
- `vision/settings.py` は共通設定の読み込みと値の確認をします。例えばポートに文字列や範囲外の数字を書いた場合、そのまま動かさずエラーにします。

画像の横幅が640なら、中央のx=320は `320÷640=0.5` です。このように0〜1へそろえることを「正規化」といいます。画像サイズが変わっても同じ意味で扱えます。左上が(0,0)、右下が(1,1)です。

```json
{"faceDetected": true, "x": 0.52, "y": 0.41, "size": 0.28}
```

これは「顔あり、横52%、縦41%の場所、顔の幅が画面幅の28%」という意味です。顔がないときも `{"faceDetected":false}` を送るため、「顔なし」と「送信が止まった」を区別できます。

## UDPとは

同じPCの `127.0.0.1:5005` に数値を届ける仕組みです。127.0.0.1は自分のPC、5005は受け取り口の番号です。インターネット上のサーバーへ送るわけではありません。

UDPは届いたことを毎回確認しません。この作品は次々に新しい位置を送るので、古い位置を全部順番に処理するより、最新の位置を使うことを優先しています。送信に成功しただけでは、Unityの受信成功まで証明できません。

## Unityの役割

- `UdpVisionReceiver.cs` は別スレッド（描画とは別に働く係）で受信します。受信待ちで画面が止まらないようにするためです。受信係は文字列を置くだけにして、JSONの解析やUnityオブジェクトの操作はメインスレッドで行います。
- 有効なデータが既定0.5秒間届かなければ、顔なしと同じくマーカーを隠します。不正なデータが届いても、この制限時間は延長しません。
- `FaceFollower.cs` は0〜1の座標をCanvasの座標へ変換します。左右反転なら `1-x`、上下反転なら `1-y` を使います。
- `Vector2.SmoothDamp` で円を徐々に目的地へ近づけます。`smoothTime=0.08` は動きの調整値であり、「システム全体の遅延が必ず80ミリ秒」という意味ではありません。初回・再登場時は直ちにその位置へ表示します。
- `CircleMarker.cs` は三角形を組み合わせて円を描きます。描画にはCanvasRendererが必要です。以前の黒画面はこの部品の不足が原因だったため、必須部品の指定と自動テストを追加しています。
- `VisionSettings.cs` はPythonと同じ `config/vision.json` を読みます。設定を変えた後は両方を再起動します。

## テストで分かること

自動試験は数値の変換、不正データの拒否、送信停止からの復帰、マーカーの状態などを繰り返し確認できます。顔が映りやすい照明、反射、自然な見え方は人が実物を見て確認する必要があります。

ユーザー確認では実顔追従、方向、退出・再登場、気にならない程度の体感遅延、約5分の連続動作が報告されています。人工データ試験を長く動かしても、実カメラや店舗での長時間運用を確認したことにはなりません。
