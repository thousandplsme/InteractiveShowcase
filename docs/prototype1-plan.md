# Prototype 1 実装計画

作成：2026-10-26。2026-10-27にこの計画に基づく実装・自動検証を実施。
この文書は計画として残し、実行結果は [prototype1-results.md](prototype1-results.md) に分けて記録します。

## 1. 目的と確定した方向性

顔に反応する体験の開始・終了・再受付を成立させる。展示は通常配置のラップトップ（横長画面）、主な対象は店の前を歩いて通り過ぎる人。隣のゲーム・ホビー展示には家族連れや子どもの関心が集まるとのユーザー報告がある。

将来はスロット風の演出を使った運だめしへ発展させる。おみくじ／ガチャの最終選択は未確定。Prototype 1は円の色変更と挨拶までに限定し、抽選や待機アニメーションは作らない。

店長はインタラクティブ作品の方向性に関心を示したとの報告あり。設置条件・撮影案内・安全管理の承認済みとは扱わない。

## 2. 前提となる既存成果

- Prototype 0のPython顔検出、UDP、Unity受信・追従、既存URPを再利用する。
- ユーザー確認済み：実顔追従、左右上下の方向、退出／再登場、体感遅延、約5分動作。追加報告として、操作・復旧手順に沿った起動と検証も完了。個別の障害試験すべてを実施したとは解釈しない。
- 既存のPython 11件・Unity 27件、人工通信10分はPrototype 0の過去の結果。Prototype 1の合格には流用しない。
- Python 3.11.9、Unity 6000.3.27f1、既存パッケージの版を維持する。既存シーンとv0.1.0配布物を上書きしない。

## 3. 体験の仕様

| ID | 仕様 |
|---|---|
| R01 | 有効な顔データがある間は既存の円が追従する。顔なしでは円を隠す |
| R02 | 顔の連続検出が開始待ち時間に達したら、1回だけ挨拶を開始する |
| R03 | 開始前に顔なしを検出したら、開始待ち時間を数え直す |
| R04 | 挨拶中は円を緑にし、中央に「こんにちは！」を表示する |
| R05 | 挨拶中に顔が消えても文字は表示時間の最後まで維持する。円だけ隠す |
| R06 | 挨拶中に顔が戻れば緑の円の追従を再開する。文字の期限は延長せず、挨拶を再発火しない |
| R07 | 挨拶終了後は文字を消し、円を通常色へ戻す。顔が映っている限り次の挨拶を始めない |
| R08 | 挨拶終了と、連続した顔なし時間が退出待ち時間に達することの両方で再受付する |
| R09 | 通信途絶・受信停止・エラーでは円と挨拶を消し、すべての体験タイマーをリセットする。復旧後は開始待ちからやり直す |
| R10 | アプリ起動、コンポーネントの再有効化時は前回の体験を引き継がない |
| R11 | 常設の案内文とプライバシー説明を表示する。通信異常で消す「文字」は挨拶を指し、常設案内は維持する |
| R12 | 設定を変えて時間を調整できる。画像・実顔座標・個人情報を試験ログへ保存しない |

### 時間の初期値

| 設定名（案） | 初期値 | 計測開始 |
|---|---:|---|
| detectionHoldSeconds | 1.0秒 | 受付可能な状態で、最初に有効な顔ありを観測した時刻 |
| greetingSeconds | 2.0秒 | 挨拶開始時刻 |
| exitHoldSeconds | 1.0秒 | 挨拶開始後、最初に有効な顔なしを観測した時刻 |

秒数は目視で調整する仮値。受信タイムアウトは既存の0.5秒を維持する。退出待ちの1秒と通信タイムアウトの0.5秒は別の条件。

### 実装上の補完ルール

- 開始・表示・退出の境界は経過時間が設定値以上になった最初の更新で成立する。フレーム数で数えない。
- 退出時間は挨拶中から数える。ただし顔が戻るたびにゼロへ戻す。以前の退出成立を覚えておき、再登場中に再受付することはしない。
- 挨拶中に退出が1秒続いても、文字の2秒は短縮しない。表示終了時に顔なしが継続していれば受付へ戻れる。
- 通信異常判定を、挨拶完了・再受付・新規開始より優先する。切断と期限到達が同じ更新でも挨拶を発火しない。
- 「連続検出」はUnityが観測した最新の有効状態の連続を指す。現在のUDPは最新1件方式なので、全カメラフレームの履歴を保証する意味ではない。
- 顔が消えた瞬間は「有効な顔なしを受信した時点」。Python強制停止は即時検知ではなく、既存タイムアウトの成立後にR09を適用する。
- 待機中はNoFace通知を何秒受け取っても開始しない。無通信の時間を「顔なしが続いた時間」として扱わない。
- 再受付に個人識別を使わない。同じ人が退出して戻っても体験可能。他人へ切り替わっても顔ありのままなら再発火しない。

## 4. 状態遷移

| 状態 | 主な動作 | 遷移 |
|---|---|---|
| Offline（有効通信なし） | 挨拶なし、タイマー消去 | 有効NoFace→Ready、有効Tracking→Qualifying |
| Ready（受付可能） | 通常色、挨拶なし | Tracking→Qualifying |
| Qualifying（開始判定中） | 通常の顔追従 | 顔ありが1秒→Greeting、NoFace→Ready |
| Greeting（挨拶中） | 緑の円＋挨拶。円の可視性は顔の有無に従う | 2秒経過時、NoFaceが1秒継続中ならReady、それ以外はAwaitExit |
| AwaitExit（退出待ち） | 挨拶なし、通常色。顔があれば追従 | NoFaceが1秒継続→Ready |

どの状態からも通信異常→Offline。状態変更はUnityメインスレッドで行う。
受信状態のTracking／NoFaceだけを通信正常とし、Waiting／TimedOut／Stopped／Errorは体験側ではOfflineに対応させる。

## 5. 表示

- 上部の常設案内：「顔を向けると反応するよ！」
- 中央の挨拶：「こんにちは！」。既存の追従円より文字が読みやすくなる描画順・余白にする。
- 下部：「カメラで顔の位置を検出しています。映像は保存しません。」
- 背景、通常の円の色はPrototype 0を土台にする。挨拶中だけ緑へ変える。色はInspectorで調整できるようにする。
- 既存のuGUI Canvas、横長1920×1080基準を利用する。文字サイズ・余白は仮値で構築し、ラップトップ実画面と展示距離で後から確認する。
- 現在Assets内にttf／otfはない。実装時に利用・同梱条件を確認できる日本語フォントを選び、出典・版・ライセンスを記録する。PCのフォントを無確認で流用しない。必要な表示文字の欠落を機械的に検査する。
- ボタン、音、3D、Particle、Shader演出、図柄の回転、ランキング、抽選結果は追加しない。

既存のFaceFollowerが円の位置・可視性を管理し、新Controllerは円の色と挨拶を管理する。両方から円のSetActiveを競合して呼ばない。Controllerは非表示にする円や挨拶自身には付けず、常時有効な管理オブジェクトに置く。

タイマーはTime.timeScaleに依存しない単調増加時刻を使う。純粋な状態機械にはテストから時刻を渡せるようにし、Coroutineや実時間sleepを単体試験に必要としない。

### 既存コードから分かった注意点

1. UdpVisionReceiver.Stateで顔なしと途絶を区別できる。TryGetFaceのfalseだけで退出判定すると、通信停止を退出と誤認するためStateを使う。
2. vision/settings.pyとVisionSettings.csは設定項目を厳密に検査する。config/vision.jsonへP1項目を混ぜず、別ファイルで既存Pythonとの互換性を保つ。Python／UDPの変更は原則不要。
3. P1設定が欠落・不正なら挨拶機能を開始せず、Consoleへ設定エラーを1回表示する。既存追従まで停止させず、黙って別の秒数で動かさない。
4. Tools/BuildWindows.cs、package_release.py、verify_package.pyとStartShowcase.cmdはP0出力を前提とする。P1の明示的な対象指定または入口を用意し、既定のP0動作を維持する。P0のZIPにP1が混ざらないことも検査する。
5. P0のValidationProbeは位置と円の描画を確認するもので、挨拶の回数・時間は確認できない。P1の観測項目を追加するが、製品の状態判定をプローブへ移さない。

## 8. 完成条件と人間の確認

機械的な完成条件は [テスト計画](prototype1-tests.md) の必須項目成功。実顔での最終受入は別に記録する。

- 約1秒の待ちが自然か。通行人が自分への反応だと分かるか。
- 顔を外しても挨拶が最後まで表示されるか。戻ったときに意図せず再発火しないか。
- ラップトップで日本語が読めるか。円と文字が邪魔し合わないか。
- Python停止／再開後に見た目も正常へ戻るか。
- 通行距離・照明・反射を含む店頭の注目効果、案内の掲示方法は別途確認する。

この計画作成の時点では、アプリ変更、フォント取得、ビルド、P1試験実行は行っていない。
